PS-03 Hackathon Submission

SkillForge

Students are told to “learn what the job needs.” Nobody tells them what they already have, what is missing, or what order to learn it in. SkillForge measures all three — and computes the path.

01 The problem

A student’s real blocker isn’t motivation.
It’s not knowing the order.

Invisible starting point

“I think I know Python”

Self-rating is the only signal most platforms have. It is unverified, inflated, and impossible to compare against what a role actually requires.

Invisible target

“Become an AI Engineer”

A job title is not a curriculum. The gap between a student and a role is a set of specific skills at specific levels — and nobody computes it.

Invisible sequence

“Just start somewhere”

Skills have prerequisites. Learning Pandas before NumPy wastes weeks. A generic “top 10 roadmap” article knows nothing about the learner.

Every generic AI study-plan tool answers the same way: it asks a language model to invent a list. The list is plausible, unverifiable, and different every time. That is the thing we set out not to build.
02 Alignment — UN Sustainable Development Goals

SDG 4 · Quality Education

Target 4.4 — “substantially increase the number of youth and adults who have relevant skills, including technical and vocational skills, for employment and decent jobs.” Two design decisions map to it directly, and neither is decorative.

Relevant skills — measured, not claimed

Proficiency is earned

A level is written from a graded sitting at level = round(1 + ratio × 4), tagged source: "assessment". “Relevant skills” becomes a number the system can defend, not a checkbox a student ticks.

Retention — the part everyone skips

Mastery has to survive the month

Every demonstrated skill is scheduled with FSRS spaced repetition, keyed on the skill rather than a flashcard. Proficiency decays and must be re-earned — so “mastered” still means something in six weeks.

Secondary — SDG 8, Decent Work

Every roadmap terminates in a real target role with weighted requirements, so learning effort is pointed at employability rather than at content consumption.

Access

Self-hosted, one command from a fresh clone, no paid dependency in the learning path. The whole system runs on a single VPS.

03 The solution

One table. Three views. Zero invented structure.

skills is a single table with an altitude enum — CATEGORY / SUBCATEGORY / SKILL. Two structures sit over it, and the third view is derived, not stored.

via skillPrerequisites

derived — not a third structure

Roadmap

04 The engine

Assessment → evidence → schedule

The scoring path is where most projects hand-wave. Four decisions here are the difference between a demo and a system.

01 Questions are tagged to skills, not to a quiz. One sitting of ten questions writes proficiency across several skills, so a single assessment moves multiple nodes in the graph.
02 Every question in the bank is graded — not just the answered ones. An unanswered question is wrong. Omitting it would silently inflate the score.
03 A quiz cannot erase better evidence. The upsert carries a setWhere restricting it to rows whose source is self_reported or assessment. A level earned from a shipped project or a certification survives a bad morning.
04 Results are sorted worst-first. The per-skill breakdown opens on what to fix, not on what went well.
The readiness rule — measured, not guessed

A prerequisite counts at half the level the role asks

Requiring the full level locked Unit Testing behind Object-Oriented Programming going 3→4 — not a real blocker. Requiring any level above zero left Pandas “startable” with NumPy at 1 of 4. Half is the rule that matches what a student expects from both. It is pinned by test at 1 (blocks) and 2 (unblocks) for a requirement of 3.

FSRS · skill-service/src/scheduler.ts

Spaced repetition, keyed on the skill

skill_state is keyed (userId, skillId), not on cards, and one module is the only importer of ts-fsrs. Fuzz is off, so the schedule is reproducible during judging. GET /progress/due already answers “what decays next.”

06 AI — the thesis

The model never decides structure.
It only describes it.

This is the single most important engineering decision in the project, and it is enforced in code, not in a prompt.

Computed — Python, deterministic

Everything that is a claim

  • Which skills are missing — a weighted vector comparison against the role’s requirements
  • What is startable versus locked — the half-level prerequisite rule
  • What order the phases go in — rank of a topological sort over the DAG
  • Effort estimates per phase
Generated — DeepSeek, gold in the UI

Everything that is prose

  • The roadmap’s narration
  • Each phase’s rationale

Two database columns. That is the entire surface the language model writes to.

Because ordering is a topological sort and not a prompt, the same student always gets the same sequence — and the roadmap is correct rather than merely plausible. This is also the reason an AI roadmap here does not read generic.
06a Generative AI

Prose written last, on a leash

skill-service settles the phases, then posts the finished plan to ai-service /narrate. Three guardrails keep it honest.

01 It is given the phases as facts. Titles, order, week estimates and skill names go in with an instruction not to re-order, merge, rename, add or drop any of them.
02 A rationale for a phase number that was not sent is dropped, not stored. Writing it would be the one remaining way a model could reshape a plan it was only asked to describe.
03 It fails soft, on a 20-second budget. An unreachable or unconfigured ai-service leaves both columns null, changes nothing else, and the response says narrated: false. The roadmap still saves. A roadmap that failed because a model was slow is a worse product than a roadmap with no prose.
Rendered in the --ai gold block on /roadmap

“You already have the Python and Git foundations this role assumes, so Phase 1 starts where the evidence stops — NumPy, then the array thinking Pandas depends on…”

Gold is reserved, app-wide, for model output. A student can see exactly which sentences a model wrote — and which numbers it did not.

Show a judge what RAG did

/search returns retrieval with no generation

A dedicated endpoint that exposes the retrieved chunks alone — so “is this really RAG?” is answerable in one request, without a model in the way.

In the UI

Citations are interactive

Answers cite sources as [1], [2]; the UI renders each as a hoverable superscript linked to the exact retrieved chunk. Multi-turn, with a past-chat switcher and retry on failure.

The detail that makes it useful

It knows you took the assessment

The assistant receives your recent sittings and the three weakest skills off the newest breakdown — so “how did I do?” and “what should I review first?” are answered from your results. If you haven’t taken one, it says so instead of inventing a score.

The corpus ships inside the ai-service image, and the service embeds all of it before opening its port — so the first question a judge asks is not the one that pays for the model load.

A deliberate cost decision

The agent pulls, it isn’t pushed

/agent is sent the assessment context but never renders it into the prompt — it reads attempts through the tool instead. A conversation that never asks about a score never pays a token for one.

Why four of six call Python

The agent reasons; it doesn’t compute

Every number the agent reports comes back from python-analyzer. The model chooses which question to ask and how to explain the answer — it never does the arithmetic that the recommendation rests on.

07 Architecture

Nine services, one database boundary

Service names match the diagram in the requirements PDF exactly.

Why a gateway at all

The frontend knows five path prefixes and no hostnames. Adding a service is one line in a route table and a compose block — nothing in the UI changes.

Why same-origin is not cosmetic

A cross-origin gateway needs SameSite=None cookies, which need TLS — which would make a plain docker compose up unable to sign anyone in.

Why one database

The gap calculation is a join between student_skills and role_requirements. Split the databases and that join becomes an HTTP call in a loop.

07a Identity & trust

Three rules, verified both ways

01 The session is verified once, at the gateway, against a live database row — not a JWT signature. Which means signing a student out actually signs them out.
02 Identity travels as headers, and the gateway strips any the client sent before adding its own. A forged x-skillforge-user-id never survives the hop.
03 Services believe those headers only with the gateway key. A request reaching a service directly carries no identity; a wrong key is a 401, not a quiet fallback to anonymous. Tested both ways — forged through the gateway, and forged straight at a service.
Authorization lives at the data layer

A mentor is a join, not a role string

A mentor reads a student only if a mentorships row joins them — requireReadAccess in profile-api. Holding the role grants nothing on its own, and a mentor may look, never edit.

The rule people forget

An admin cannot demote themselves

The last one doing so would leave nobody able to promote anyone back. The first admin is made from outside the app — ./scripts/promote.sh.

Defence in depth

Not published, and not trusted either

Postgres has no ports: entry at all, and Kubernetes adds NetworkPolicies. But network reachability is one mistake from being wrong — so a forged header fails closed rather than depending on the network being right.

08 DevOps

Infrastructure that describes a system that exists

A generic AWS skeleton would have been faster and more familiar to a judge. It also would have described a deployment we do not run — decorative infrastructure is exactly what the rubric punishes.

Docker Compose

Dev and production, one file

10 services, 4 volumes. The same docker-compose.yml a judge runs locally is the one deployed via Coolify on a Contabo VPS. Every image builds from the repo root, because ai-service copies the RAG corpus in.

Kubernetes

26 resources · 14 files · all valid

Every service in the compose file has a Deployment. Validated with kubeconform -strict against real 1.31 schemas — offline, and it rejects unknown fields, which is what catches a mistyped key.

Terraform

The box that actually runs it

Targets the contabo/contabo provider directly, and uses existing_instance_id to adopt the VPS already running Coolify rather than ordering a second one. Plus cloud-init.

Shipped — verified on the live box Live skillforge.sudobox.tech
  • / — 200, valid Let’s Encrypt certificate
  • /api/skills/roles — four roles, through the gateway
  • /api/ai/health — llm_configured and embeddings_ready both true, 140 chunks

And from nothing: ./scripts/setup.sh generates .env with fresh secrets, builds, starts, health-gates and seeds. Safe to re-run.

Details that only show up in production
  • ai-service runs one replica with a 5-minute startupProbe — each replica embeds the corpus at boot and shares nothing.
  • Every Dockerfile installs with --linker=hoisted: Bun’s isolated layout breaks Next’s file tracer, and that failure appears at container start, not at build.
  • Seed ids are deterministic from slugs, so re-seeding updates rows in place instead of orphaning the attempt answers pointing at them.

10 Engineering judgment

What we chose not to build

Every rejected idea is written down with its reason, in docs/decisions.md, so nobody on the team re-proposes it — and so a judge can see the call was made rather than missed.

Not builtBecause
An LLM that orders roadmap phasesOrdering is a topological sort. A model writes prose, never structure.
pgvector for RAG140 chunks — a linear scan beats a network round trip. The column is there; revisit past a few hundred.
Supabase / VercelAn all-managed deploy makes the compose file, the K8s manifests and the architecture diagram describe a system that does not exist.
Broadening past tech careersThe brief says technology. The graph is more convincing dense and narrow than sparse and wide.
Assessment authoring UILarge build, small marginal credit — and the honest gap against the brief, stated as one rather than hidden.
Tighter auth rate limitsLoose is the right failure mode while five judges hit the same instance.
Everything degrades instead of breaking

Three fallbacks, all reported

Analyzer unreachable → TypeScript topological layering, and the response says which ran. Narration slow → narrated: false, plan still saves. Assistant context fails → the answer still comes back. Nothing in the demo path has a single point of failure.

An approved deviation, documented

PostgreSQL, not MongoDB

The PDF’s generic cross-problem diagram names MongoDB; PS-03’s own service diagram names no database at all — and that is the one we match exactly. We asked the organizers and got explicit permission, then recorded it in docs/decisions.md so it reads as a decision, not a miss.
