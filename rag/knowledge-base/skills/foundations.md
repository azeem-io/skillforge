# Foundation skills

The skills nearly every technology path depends on. Weakness here shows up later
as difficulty that appears to be about something else.

## Python

A general-purpose language used for scripting, web backends, data work and
automation. Readable enough to learn first, deep enough to still be using in ten
years.

Being "comfortable with Python" means classes, error handling, virtual
environments and packaging — not just syntax. The gap between someone who can
follow a tutorial and someone who can debug an unfamiliar traceback is mostly
this.

## Control flow and loops

Conditionals, iteration, and the shape of a program. Language-agnostic: once you
have it in one language, you have it in all of them, which is why it should not
be treated as belonging to Python or JavaScript specifically.

## Object-oriented programming

Classes, encapsulation, inheritance and composition. The useful skill is not
writing classes — it is knowing when a class earns its place and when a function
would be clearer. Overuse is as common a failure as underuse.

## Data structures

Lists, dictionaries, sets, and knowing the cost of each operation. Choosing a
list where a set belongs turns an instant lookup into a scan, and it is one of
the most common causes of code that works fine on test data and crawls on real
data.

## Algorithms

Sorting, searching, and complexity analysis. The point is not memorising
implementations — it is recognising when something you wrote is quadratic and
did not need to be.

## Unit testing

Tests that pin behaviour so refactoring is survivable. The discipline that
matters most: a test that has never failed has not been shown to test anything.
Break the code deliberately and confirm the test notices.

## Git

Version control. Branching, merging, and resolving conflicts without panic.
Nearly every developer learns just enough Git to get by and then avoids it —
spending an afternoon on rebase, reflog and reset pays back for years, because
it turns "I broke everything" into a recoverable situation.

## SQL

Querying relational data. Joins and aggregation are where most people stop and
where most of the value starts. Reading a query plan is the difference between
guessing at slowness and diagnosing it.
